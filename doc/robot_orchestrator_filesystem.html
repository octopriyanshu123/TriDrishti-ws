Naming conventions

I<Name>.h — pure abstract interface
<Name>.h / .cpp — concrete implementation
config.yaml per HAL — loaded at HAL startup
Each module folder owns its own CMakeLists.txt
Shared types never include module headers — no circular deps

Key interface contracts

IHalDevice — every HAL must implement init(), start(), stop(), send(HalCommand)
IOperationManager — setMode(), dispatch(Command)
IStateManager — transition(StateEvent), currentState()
ILogger — log(severity, msg, context)

Startup sequence

1. main.cpp loads orchestrator.yaml & i2w_endpoints.yaml
2. LoggerManager initialised first (all logs from here on captured)
3. HAL processes are spawned as child processes; HAL Controller waits for their I2W registration
4. StateManager enters INIT → READY once all HALs have registered
5. UI Interface opens I2W socket; UI connection unblocks READY → RUNNING
