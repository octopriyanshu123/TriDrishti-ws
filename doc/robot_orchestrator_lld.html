Robot Orchestrator — Low-Level Design

Linux process architecture · I2W IPC · HAL per hardware device · PID control

Operation modes

Teleop: Real-time joystick/UI commands forwarded through the Operation Manager to the PID Controller and then to the HAL Controller. Low-latency path — priority queue.

Behaviour Tree (BT): Autonomous mission. The BT engine ticks periodically; leaf nodes post actions to the Operation Manager's command queue. State Manager guards all transitions.

I2W IPC design notes

The Orchestrator owns the I2W bus. Each HAL process registers its endpoint at startup. The HAL Controller maintains a per-device command queue and sends typed messages over I2W. Responses (sensor data, ack) travel the same channel back. Crash in one HAL PID does not crash the Orchestrator — the HAL Controller detects the dropped connection and triggers the NDT Fault Handler.

PID Controller placement

Lives inside the Orchestrator process (not a separate HAL) so it can run at a deterministic control rate. It reads setpoints from the Operation Manager and joint feedback from the MyActuator HAL, then emits torque/velocity commands back through the HAL Controller. Gains are loaded from a config file per joint at startup.

State machine transitions

INIT → READY → RUNNING ⇄ PAUSED → SHUTDOWN
E-stop (from NDT Fault Handler or UI) forces any state into ESTOP, which disables all actuator commands. Recovery requires an explicit reset from the UI. The State Manager broadcasts every transition to Logger Manager and UI Interface.
